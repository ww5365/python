### 3.1 python日志分析

#### 3.1.1 构建期：参数仅在图定义中，尚未分配显存

```
04_after_build_engines:   tf_var_est: emb=2172.4, slot=0, dense=0
05_after_build_forward_graph: tf_var_est: emb=2172.4, slot=0, dense=755.5
06_after_build_full_graph_backward: tf_var_est: emb=2172.4, slot=5855.7, dense=755.5
```

- **Embedding 变量总大小**：2172.4 MB（对应 8,898,031 行 × 嵌入维度 × 4 字节）
- **DCN 网络变量总大小**：755.5 MB
- **Adam 优化器 slot 变量总大小**：5855.7 MB（约为 embedding 参数的 2.7 倍，符合 Adam 需要 `m` 和 `v` 两份状态）
- **模型与优化器总参数理论值**：2172.4 + 755.5 + 5855.7 = 8783.6 MB

此时 NPU HBM 仍未分配，停留在初始 ~3276 MB。

#### 3.1.2 变量实例化：显存跃升

```
10_after_global_variables_initializer:
  NPU_HBM=17694MB (+14418MB)
```

`global_variables_initializer` 执行后，所有 TF 变量在 NPU HBM 上实际分配。

分配的模型+优化器参数 ≈ 8784 MB，但此时总增长为 14418 MB，多出约 5634 MB，这部分是：
- NPU 初始化开销
- 图执行引擎所需的设备内存（常量、控制流结构等）

#### 3.1.3 首次迭代后：峰值显存

```
iter0_after_full_train_step:
  NPU_HBM=52428MB (+49152MB)
```

首次完整前向+反向+更新后，HBM 从 17694 MB 飙升至 52428 MB，额外增长 34734 MB。

这部分全部是运行时缓冲区：
- 中间激活值（DCN 各层的输出，batch size 较大时占比高）
- AlltoAll 通信缓冲区（发送/接收的 embedding 块）
- 梯度张量、中间计算图缓存
- NPU 算子工作空间

后续迭代 HBM 基本稳定在 58982 MB（最终峰值 55706 MB 增量），说明缓冲区被复用，没有持续泄漏。
